# 从本机到公网：第一次上线操作教程

核对日期：2026-10-06。适用范围：全新 Debian 13 云服务器、一个域名、同机 Caddy + Waitress、单个应用实例。其他系统、已有网站的服务器、CDN 或多层代理需要调整，不能直接套用。

目前代码具备部署条件，52 项回归测试通过；真实服务器、HTTPS 和公网访问尚未验收。先上线官网展示，本站收费售票保持关闭。部署完成后仍须执行第 10 步。

## 1. 准备服务器和域名

购买一台有公网 IPv4 和持久磁盘的 Linux 云服务器，以及一个自己的域名。小规模官网可从 1–2 核、2 GB 内存开始评估；这不是已验证的并发容量。选择 Debian 13 系统，它提供 Python 3.13，与本机测试的大版本一致。[Debian 软件包](https://packages.debian.org/trixie/python3.13)

如果两天内需要演示，而尚未备案，可评估香港或海外节点的实际访问效果。使用中国内地服务器须先完成 ICP 备案，不能把两天作为审核完成的保证。香港、海外节点的 ICP 要求不同，公安联网备案等要求仍须按实际主体和服务范围核对。[接入商备案说明](https://help.aliyun.com/zh/icp-filing/basic-icp-service/user-guide/icp-filing-application-overview)

下文的 `band.example.com` 是示例，必须全部换成你的真实域名。`203.0.113.10` 是示例 IP，不能用于部署。建议先使用一个主域名，暂不增加 www、CDN 或其他代理。

在云控制台的安全组/防火墙中设置入站规则：

| 协议/端口 | 来源 | 用途 |
| --- | --- | --- |
| TCP 22 | 你的管理网络公网 IP | SSH 管理；IP 变化后更新规则 |
| TCP 80 | 所有来源 | HTTP 跳转与证书验证 |
| TCP 443 | 所有来源 | HTTPS 访问 |

不要开放 8000、5000 或数据库端口。若系统内另有防火墙，也需要允许对应端口。创建服务器时优先配置 SSH 密钥，并妥善保存私钥。

## 2. 建立两个终端窗口

窗口 A 始终是你电脑上的 PowerShell；窗口 B 用于 SSH 登录服务器。下文分别标注执行位置。

**窗口 A，本机：**

```powershell
Set-Location 'D:\website\suzhou-quintet-v0.1\suzhou-quintet'
$server = '203.0.113.10'
$sshUser = 'root'
```

替换 IP 和 SSH 用户名，以云平台提供的登录信息为准。若使用指定密钥，ssh/scp 都追加 `-i '你的私钥路径'`。

**窗口 B，本机执行登录：**

```powershell
ssh root@203.0.113.10
```

同样替换用户名和 IP。核对首次连接的主机指纹；确认登录成功后，窗口 B 后面的命令就是 Linux 命令。

**窗口 B，服务器：**

```bash
mkdir -m 700 /tmp/sq-deploy
sudo -i
```

如果已经是 root，第二行可以省略。若 mkdir 提示目录已存在，先检查它的来源和权限，不要继续往未知目录上传私密备份。后续服务器命令均在这个 root 管理终端执行；网站应用本身会用受限账号 sq 运行。

## 3. 本机核对内容，备份真实资料并上传

先在本机后台核对成员介绍、演出日期、照片和联系渠道；每个场次的“开启售票”保持未勾选，测试场次保持“内部测试场次”。公开展示前核对成员履历与演出介绍的准确性。

停止其他人编辑本机资料，在窗口 A 生成新的完整备份。使用全新的 PowerShell 窗口，避免继承以前手动设置的生产环境变量。

**窗口 A，本机：**

```powershell
$dataZip = Join-Path (Get-Location) ('maintenance-backups\migration-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.zip')
.\.venv\Scripts\python.exe -m flask --app app backup --full "$dataZip"
.\.venv\Scripts\python.exe -m flask --app app verify-backup "$dataZip"
```

必须看到校验通过；出现错误就停止。备份后不要再编辑本机内容，直到迁移完成，避免两份数据发生分歧。

已准备的源码包只包含运行代码、模板、静态资源和部署示例，不包含 .venv、数据库、上传照片或密钥。若之后改过代码，按下列命令重新生成一个新源码包：

```powershell
$sourceZip = Join-Path (Get-Location) ('maintenance-backups\source-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.zip')
.\.venv\Scripts\python.exe -m zipfile -c "$sourceZip" app.py config.py db.py gallery_uploads.py maintenance.py public_pages.py security.py serve.py ticketing.py schema.sql requirements.txt templates static deploy
```

或者使用本次已准备的源码包：

```powershell
$sourceZip = Join-Path (Get-Location) 'maintenance-backups\source-for-deploy-20261006.zip'
```

任选一种设置 sourceZip，接着上传：

```powershell
scp "$sourceZip" "${sshUser}@${server}:/tmp/sq-deploy/source.zip"
scp "$dataZip" "${sshUser}@${server}:/tmp/sq-deploy/data.zip"
```

完整数据包含私密信息，只通过 SSH 传输，不放公开网盘、公开仓库或网页目录。不要把 Windows 的 .venv 上传到 Linux，也不要直接复制运行中的 SQLite 文件。

## 4. 安装系统组件与 Caddy

**窗口 B，服务器：**

```bash
apt update
apt upgrade -y
apt install -y python3 python3-venv unzip curl gnupg debian-keyring debian-archive-keyring apt-transport-https
python3 --version
```

Python 应为 3.13.x。系统提示需要重启时按提示处理，重新连接后进入 root 终端，再继续。

安装 Caddy 官方稳定版软件源与软件包：[官方安装说明](https://caddyserver.com/docs/install)。

```bash
curl -fsSL https://dl.cloudsmith.io/public/caddy/stable/gpg.key -o /tmp/sq-deploy/caddy.gpg.key
gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg /tmp/sq-deploy/caddy.gpg.key
curl -fsSL https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt -o /etc/apt/sources.list.d/caddy-stable.list
chmod 644 /usr/share/keyrings/caddy-stable-archive-keyring.gpg /etc/apt/sources.list.d/caddy-stable.list
apt update
apt install -y caddy
```

任何下载、签名转换或安装出错都先处理，不要跳过。官方软件包会安装 Caddy 的 systemd 服务。

## 5. 安装项目，恢复到新的持久目录

只适用于首次部署。如果以下目录已经有网站或真实数据，停止并按更新/恢复流程处理，不能覆盖。

**窗口 B，服务器：**

```bash
useradd --system --user-group --home-dir /var/lib/suzhou-quintet --shell /usr/sbin/nologin sq
install -d -m 755 /opt/suzhou-quintet
install -d -o sq -g sq -m 700 /var/lib/suzhou-quintet
unzip /tmp/sq-deploy/source.zip -d /opt/suzhou-quintet
unzip /tmp/sq-deploy/data.zip -d /tmp/sq-deploy/restore
install -o sq -g sq -m 600 /tmp/sq-deploy/restore/band.sqlite3 /var/lib/suzhou-quintet/band.sqlite3
install -d -o sq -g sq -m 700 /var/lib/suzhou-quintet/uploads
cp -a /tmp/sq-deploy/restore/uploads/. /var/lib/suzhou-quintet/uploads/
chown -R sq:sq /var/lib/suzhou-quintet
chmod -R go-rwx /var/lib/suzhou-quintet
cd /opt/suzhou-quintet
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip check
```

当前项目有上传图片，因此 uploads 存在。若使用一份从未上传图片的空备份，没有 uploads 目录，可以省略 cp 那一行。

数据与代码分开存放：以后换源码包不应替换 /var/lib/suzhou-quintet。这里使用新的生产密钥，不复用本机开发密钥，因此本机已有登录 Cookie 不会迁移生效；订单等数据库记录保留。

## 6. 写入生产配置并重设管理员

**先把下面两处 band.example.com 改成真实域名。窗口 B，服务器：**

```bash
umask 077
cat > /etc/suzhou-quintet.env <<'EOF'
SQ_ENV=production
HTTPS_ONLY=1
PUBLIC_BASE_URL=https://band.example.com
TRUSTED_HOSTS=band.example.com
PROXY_HOPS=1
SQ_INSTANCE_PATH=/var/lib/suzhou-quintet
PYTHONDONTWRITEBYTECODE=1
EOF
python3 -c 'import secrets; print("SECRET_KEY=" + secrets.token_hex(32))' >> /etc/suzhou-quintet.env
chmod 600 /etc/suzhou-quintet.env
set -a
. /etc/suzhou-quintet.env
set +a
cd /opt/suzhou-quintet
```

为避免扩大私密上传目录的权限，使用下面的受限临时副本执行服务器校验：

```bash
install -o sq -g sq -m 600 /tmp/sq-deploy/data.zip /var/lib/suzhou-quintet/migration-check.zip
runuser -u sq --preserve-environment -- .venv/bin/python -m flask --app app verify-backup /var/lib/suzhou-quintet/migration-check.zip
```

必须看到校验通过再继续。环境文件只创建一次，后续维护不要重新运行创建文件和生成密钥的几行。正式密钥应固定，单独私密备份，不要贴到聊天中。

重设每个现有管理员账号的密码，撤销备份中可能包含的旧工作人员登录。要输入原来的用户名；输入新用户名会新增账号，不能重设原账号。

```bash
runuser -u sq --preserve-environment -- .venv/bin/python -m flask --app app set-admin
runuser -u sq --preserve-environment -- .venv/bin/python -m flask --app app check-deployment
```

set-admin 会询问用户名和两次密码，密码至少 12 位，输入密码时终端不显示字符属于正常行为。有多个账号时重复执行第一条，逐个重设。第二条应该全部 PASS。若只是介绍/联系渠道缺失，可以在 HTTPS 服务启动后进入后台补齐，再重跑检查；其他配置失败应先处理。

## 7. 设置网站自动运行

**窗口 B，服务器：**

```bash
cp /opt/suzhou-quintet/deploy/suzhou-quintet.service.example /etc/systemd/system/suzhou-quintet.service
chmod 644 /etc/systemd/system/suzhou-quintet.service
systemctl daemon-reload
systemctl enable --now suzhou-quintet
systemctl status suzhou-quintet --no-pager
curl -f -H 'Host: band.example.com' http://127.0.0.1:8000/healthz
```

curl 的 Host 也必须换成真实域名。预期服务 active (running)，健康检查返回 {"status":"ok"}。本机内部检查使用 HTTP 是正常的，观众访问将由 Caddy 提供 HTTPS。

如果服务失败：

```bash
journalctl -u suzhou-quintet -n 60 --no-pager
```

先处理报错，再继续。不要为了绕过报错启用 debug、移除安全配置或开放 8000。

## 8. 设置域名解析

在域名服务商控制台打开 DNS/解析管理，新增 A 记录：

| 字段 | 内容 |
| --- | --- |
| 类型 | A |
| 主机记录 | 使用 example.com 时填 @；使用 band.example.com 时填 band |
| 记录值 | 服务器真实公网 IPv4 |
| TTL | 使用控制台默认值 |

删除或修改同一主机名下指向旧主机的冲突记录。没有配置可访问 IPv6 时，不要添加 AAAA 记录。先使用直接 DNS 解析，不开启 CDN 代理。

**窗口 A，本机：**

```powershell
Resolve-DnsName band.example.com -Type A
```

换成真实域名。结果应为服务器 IP；DNS 生效时间不固定。中国内地服务器必须先完成相应备案再开放网站。

## 9. 启用 HTTPS

**把首行域名替换后，在窗口 B，服务器执行：**

```bash
cat > /etc/caddy/Caddyfile <<'EOF'
band.example.com {
    encode zstd gzip
    request_body {
        max_size 20MB
    }
    reverse_proxy 127.0.0.1:8000 {
        header_up X-Forwarded-For {remote_host}
        header_up X-Forwarded-Proto https
        header_up -X-Forwarded-Host
        header_up -X-Forwarded-Prefix
    }
}
EOF
chmod 644 /etc/caddy/Caddyfile
caddy fmt --overwrite /etc/caddy/Caddyfile
caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
systemctl enable --now caddy
systemctl reload caddy
```

此处直接写真实域名，避免 deploy/Caddyfile.example 中 SQ_DOMAIN 未注入 Caddy 服务的问题。PROXY_HOPS=1 仅适用于这套同机单层代理架构。

DNS、80/443 端口与持久证书目录满足条件时，Caddy 自动申请/续期证书并把 HTTP 跳转到 HTTPS。[Caddy HTTPS 说明](https://caddyserver.com/docs/automatic-https)

## 10. 做公网验收，之后再分享网址

**窗口 A，本机：**

```powershell
curl.exe -I http://band.example.com
curl.exe -f https://band.example.com/healthz
```

换成真实域名，HTTP 应跳转到 HTTPS，健康检查返回 ok。不要加 -k 忽略证书错误。

在电脑无痕窗口与手机移动数据分别打开网站，按顺序检查：

1. 首页、成员、演出、往期、隐私说明，照片和链接完整，日期与联系渠道正确。
2. 浏览器证书有效；HTTP 自动跳转；手机无横向溢出。
3. /admin/login 能登录；可以保存一条真实介绍或上传一张照片，再刷新检查；退出后 /admin 要求重新登录。
4. 未登录访问草稿/内部测试不可见；测试演出不进入公开列表和 sitemap.xml。
5. /robots.txt、/sitemap.xml 可访问；本站收费售票仍关闭。
6. 服务器执行 systemctl restart suzhou-quintet，再检查后台和图片；执行一次重启服务器的验收，重新连接确认两个服务自动运行。
7. 迁移后做新备份；在另一个隔离目录恢复验证，不能拿运行中的真实数据目录做恢复试验。

可以用私有测试场次演示订单和核销，但必须明确是模拟流程，不进行真实付款。正式收款须另行验收到账、人工对账、退款及现场核销。

## 11. 建立维护习惯

完整备份每天一次，更新前再做一次。服务器 root 终端的手动命令：

```bash
set -a
. /etc/suzhou-quintet.env
set +a
cd /opt/suzhou-quintet
backup_path="/var/lib/suzhou-quintet/backups/band-$(date +%Y%m%d-%H%M%S).zip"
runuser -u sq --preserve-environment -- .venv/bin/python -m flask --app app backup --full "$backup_path"
runuser -u sq --preserve-environment -- .venv/bin/python -m flask --app app verify-backup "$backup_path"
```

使用 SSH 把通过校验的备份保存到另一处私密存储，同时单独保护 /etc/suzhou-quintet.env。同磁盘备份不能防磁盘损坏；生产环境的 SECRET_KEY 不会打进完整数据包。

源码更新时先在本机完成检查，再备份服务器数据、停止应用、替换源码及安装依赖、重新启动并验收。不要覆盖持久数据目录，不要反复执行首次恢复步骤。疑似账号泄露时用 set-admin 重设对应账号密码。

日志排查：journalctl -u suzhou-quintet -n 60 --no-pager；证书/代理排查：journalctl -u caddy -n 60 --no-pager。502 通常先查应用服务；400 先查 Host/域名配置；证书错误先查 DNS 与 80/443。网站错误日志、备份和配置含敏感资料，分享前检查内容。

部署完成后，用相同路径把源码包和数据包从 /tmp/sq-deploy 移入仅 root 可读的归档目录，或按本人的备份策略清理；不要将它们复制到可通过网站访问的目录。
