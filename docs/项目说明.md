# 项目说明

苏州爵士五重奏官网集中展示成员介绍、演出信息和往期现场，提供内容管理后台及人工确认付款的售票流程。

## 架构与维护

网站使用 Flask 处理请求，Jinja 渲染页面，SQLite 保存成员、演出、订单与票券。图片存放在实例目录，数据库与图片需要一起备份。生产入口使用 Waitress；公网部署还需要配置 HTTPS、持久数据目录和反向代理。

| 选择 | 理由 | 使用边界 |
| --- | --- | --- |
| Flask + Jinja | 页面、表单和后台可以直接维护 | 当前采用服务端渲染 |
| SQLite 单实例 | 降低小团队的运行成本，用写事务保护库存 | 写入串行，扩容需要重新评估数据库 |
| 人工确认付款 | 配合现有收款方式，分开处理付款申报与实际到账 | 需要人工对账与线下退款 |
| 少量订单信息 | 称呼与联系方式用于订单协助 | 日志、备份和售后资料仍需管理 |

## 售票流程

1. 管理员配置收款二维码、收款人和联系渠道，在演出中设置票价、库存与售票时间。
2. 观众提交购票信息。服务器读取票价，在事务中检查库存并创建待付款订单。
3. 观众使用收款二维码付款，再提交付款申报。申报本身不能证明已经到账。
4. 管理员核对实际收款记录后确认订单，系统生成每张票独立的随机票码及二维码。
5. 工作人员查询票券后明确确认核销，服务器检查票券状态和入场时间，防止重复使用。

待付款订单有保留期限，付款申报后进入审核状态。收款二维码与入场票券二维码用途不同；当前没有接入自动支付回调或自动退款。

## 安全与验证

后台接口在服务器检查登录和权限，写入操作使用 CSRF 防护。服务端会话可以撤销，密码使用哈希保存；图片上传进行格式和内容校验。生产配置检查 Cookie、域名与代理设置，并提供备份校验工具。

回归测试覆盖库存竞争、重复操作、访问权限、会话撤销、票券核销和备份恢复等场景。具体验证结果见 [验证记录](验证记录.md)。功能测试不能替代公网环境验收或真实运营效果评估。

## 代码阅读路径

- `app.py` 与 `templates/home.html`：URL 请求、路由查询及页面渲染。
- `schema.sql` 与 `ticketing.py`：成员和演出的关联、订单状态、整数分金额与库存事务。
- `security.py` 与 `config.py`：CSRF、登录会话和生产环境约束。
- `maintenance.py`：数据库和上传文件的备份、校验与恢复。

## 功能展示

可以依次查看首页、成员、往期演出与后台内容管理，再使用内部测试场次验证订单、付款申报、人工确认、出票和核销。展示前检查测试场次的售票及入场时间；使用测试资料，避免公开真实观众信息、有效票码或后台凭据。

公开运行前按照 [一步步上线](一步步上线.md) 配置主机，并完成 HTTPS、后台访问、备份恢复与订单流程验收。GitHub 保存源代码，网站服务需要单独部署。
