# 上线与维护

更新于 2026-10-06。本项目已完成本机代码维护；服务器、域名、TLS 和公网验收待确定。官网可以先发布，继续关闭本站收费售票。

## 运行结构

浏览器 → HTTPS 代理 → 127.0.0.1:8000 的 Waitress → Flask → 持久磁盘上的 SQLite 与上传图片。

只运行一个应用实例，不把数据库放在临时发布目录或共享网络盘。库存写入通过 SQLite 写事务串行处理。Caddy 示例适用于代理与应用同机、只有一层代理。

## 环境配置

| 变量 | 设置 |
| --- | --- |
| SQ_ENV | production |
| HTTPS_ONLY | 1 |
| SECRET_KEY | 至少 32 个随机字符，建议 64 位十六进制，固定并私密保存 |
| PUBLIC_BASE_URL | 实际 HTTPS 源地址，无路径，如 https://band.example.com |
| TRUSTED_HOSTS | 确切主机名，逗号分隔，不带协议、路径或端口，包含公开地址主机名 |
| SQ_INSTANCE_PATH | 持久数据目录的绝对路径 |
| PROXY_HOPS | 默认 0；同机 Caddy 示例用 1，不能凭猜测增加 |

.env.example 是说明模板，serve.py 不会自动读取。托管平台使用其环境变量和密钥设置；Linux 示例通过 systemd 的 EnvironmentFile 注入。

Windows 示例须替换域名和路径：

~~~powershell
$env:SQ_ENV = 'production'
$env:HTTPS_ONLY = '1'
$env:PUBLIC_BASE_URL = 'https://band.example.com'
$env:TRUSTED_HOSTS = 'band.example.com'
$env:PROXY_HOPS = '1'
$env:SQ_INSTANCE_PATH = 'D:\SQ-data\instance'
$env:SECRET_KEY = .\.venv\Scripts\python.exe -c 'import secrets; print(secrets.token_hex(32))'
~~~

**密钥只生成一次并安全持久保存。** 每次启动重新生成会使现有 Cookie 失效。以上变量仅对当前进程和子进程有效，正式服务须用受保护的服务配置设置。不要把密钥贴到聊天或公开文档。

生产配置缺失、密钥过短、不安全 Cookie、域名不匹配或启用调试时拒绝启动。

## 迁移与启动

1. 完整备份并执行 verify-backup。
2. 停止本机服务，把验证过的数据库、uploads/ 和本机密钥放入持久目录。新主机重新创建虚拟环境，不复制 Windows .venv 到 Linux。
3. 安装 requirements.txt。启动会补充会话表和索引，保留现有记录。新安装可运行 setup.py，已有真实资料无需重复初始化。
4. 设置生产变量，执行 flask --app app check-deployment，按失败项补齐。
5. 运行 python serve.py，确认只监听 127.0.0.1:8000。
6. 配置同机 HTTPS 代理，公网只开放必要的 HTTPS 与证书签发入口；后台端口不可直接对公网开放。
7. 设置受限服务账号、开机启动与失败重启。deploy/suzhou-quintet.service.example 是 Linux 模板，路径和权限须按主机调整，本次未在 Linux 主机执行。

deploy/Caddyfile.example 需要设置 SQ_DOMAIN。它会重新设置来源和协议头后转发。若加入 CDN、多层网关或分离主机，须重新核对链路，不能直接沿用代理数量。

Waitress 默认清理转发头；本项目仅在设置 PROXY_HOPS 时保留给 ProxyFix，监听地址始终是回环地址。不能改成公网监听后继续信任观众可伪造的转发头。

参考：[Flask 部署](https://flask.palletsprojects.com/en/stable/deploying/)、[可信代理](https://flask.palletsprojects.com/en/stable/deploying/proxy_fix/)、[Waitress 参数](https://docs.pylonsproject.org/projects/waitress/en/stable/arguments.html)、[Caddy HTTPS](https://caddyserver.com/docs/automatic-https)。

## 公网验收

| 检查 | 预期 |
| --- | --- |
| HTTPS | 有效证书，HTTP 转 HTTPS，重启后数据和证书可用 |
| /healthz | 200，status 为 ok，不暴露账号、版本或磁盘路径 |
| 恶意 Host | 400，转发头不能绕过域名限制 |
| 官网内容 | 真实资料正确，海报、相册、视频、地图与日历可用 |
| 手机与微信浏览器 | 导航、表单、图片与票券可操作，无横向溢出 |
| 键盘 | 跳转正文、导航与表单可达，焦点清晰 |
| 草稿与内部测试 | 未登录为 404，不进入公开列表与站点地图 |
| 登录 | Secure、HttpOnly、SameSite Cookie，退出与改密码撤销旧登录 |
| 上传 | 格式限制，单图 6 MB、提交总计 20 MB、单图两千万像素 |
| 订单 | 后端计价、并发最后一张、防重复提交、密钥找回和独立票券通过 |
| 迟到付款 | 超时不显示付款码，人工重新核对余票或退款 |
| 核销与退款 | 重复核销拒绝，退款作废票券，已用票转人工争议处理 |
| 备份恢复 | 独立目录恢复，数据库与图片对应，票券关系正确 |
| 进程 | 停止后按服务策略恢复，真实请求正常 |

真实收款未验收前保持 sales_open=0。内部测试始终保持 is_test=1，严禁真实付款。正式售票须明确价格、容量、时间、退款条款及工作人员值班。

## 日常维护

- 每天及发布前备份，安全保存到另一处；同磁盘备份无法应对磁盘故障。定期在独立环境恢复验证。
- 监测健康检查、磁盘、重启与 5xx。不要记录密码、查询密钥、CSRF token 或完整表单。验票 URL 含票码，代理日志须屏蔽查询参数或限制读取和保存期限。
- 更新后运行测试、代码检查与依赖扫描，漏洞升级后重新验证关键流程。
- 各工作人员使用各自账号；设备遗失或疑似泄露时运行 set-admin 重置该账号，撤销其所有登录。
- 公开资料核对事实与照片使用授权，定期检查联系渠道；不要把观众资料放进公开页面。
- 人工处理更正或删除请求，按实际售后需要评估保留时间。本版不自动删除历史订单，也没有自助隐私请求系统。

可以定期安排 expire-orders 更新超时状态；下单与库存查询已按截止时间判断占位。大流量需要网关层保护，本次未验证压力上限或 DDoS 防御。

## 备份与恢复

~~~powershell
.\.venv\Scripts\python.exe -m flask --app app backup --full backups/band-20261006.zip
.\.venv\Scripts\python.exe -m flask --app app verify-backup backups/band-20261006.zip
~~~

完整备份取得一致数据库快照并打包图片，期间会短暂阻塞写入，应避开售票高峰。用新文件名，不覆盖旧备份。

包含 band.sqlite3、uploads/、存在时的 secret.key 和 SHA-256 清单。校验检查文件一致性、SQLite 完整性及外键。清单不是数字签名，不能证明来源可信。生产环境变量中的密钥不会写入压缩包，须单独安全备份。

恢复流程：

1. 停止应用，先备份当前数据。
2. 验证备份，解压到新的隔离目录，不能直接覆盖运行目录。
3. 恢复同一快照的数据库、图片和密钥，不能混入旧 WAL、SHM 文件。
4. 恢复快照可能同时恢复旧工作人员会话，启用服务前在隔离环境用 set-admin 重置每个账号。
5. 验证后台、资料和票券后切换服务，并与真实收款记录重新对账。

本次在临时数据上验证了恢复，没有覆盖真实数据库进行恢复。实际完整数据另行备份在忽略目录。

## 后续方向

所有管理员同权限，没有二次验证；需要时增加后台两步验证或代理访问保护。多实例运行需要迁移数据库、共享限流和文件存储。

自动支付需要可用支付账户、签名验证、金额核验、幂等回调、查单和对账。整单退款仍由工作人员线下执行，存在已核销票券时转人工处理。
